Il tuo patrimonio, senza abbonamenti.

Guida pratica della versione gratuita locale. Nessun account, carta di credito, database ospitato o API bancaria è necessario. Tutti i calcoli e le importazioni avvengono nel browser.

Da sapere prima di iniziare
I dati stanno nel browser, non nel sito. Telefono e computer hanno copie indipendenti. Cancellare i dati del browser può cancellare il patrimonio: scarica regolarmente il backup JSON. «Nascondi importi» non cifra i dati.

1. Avvia dal computer

  1. Installa Node.js 22.12 o successivo e scarica il progetto.
  2. Apri un terminale nella cartella ed esegui npm ci.
  3. Esegui npm run dev e apri l’indirizzo mostrato da Vite. Per una versione offline installabile usa invece npm run build, poi npm run preview. Mantieni il terminale aperto durante l’uso locale.
  4. Non compilare chiavi o credenziali: il file .env non serve.

2. Telefono e installazione, senza server a pagamento

Per un URL HTTPS comodo da aprire dal telefono puoi pubblicare solo l’app statica su GitHub Pages del repository pubblico. Nessun patrimonio personale viene pubblicato: viene salvato sul singolo dispositivo.

  1. Dopo il merge, apri docs/pages-workflow.yml.example su GitHub e copia il testo. Scegli Add file → Create new file, nome .github/workflows/pages.yml, incolla e salva. Questa operazione va fatta da te: la connessione dell’agente non ha permessi di modifica dei workflow. Poi apri Settings → Pages → Source: GitHub Actions. Serve essere proprietario o amministratore del repository.
  2. Apri Actions → Pubblica app gratuita su Pages → Run workflow → main. Il flusso è esclusivamente manuale e si esegue solo se il repository è pubblico. Non acquistare piani, non inserire una carta e non attivare runner a pagamento. Se GitHub propone un costo, fermati: l’uso locale resta disponibile.
  3. Attendi il completamento e apri l’URL indicato dal deployment. Il flusso gestisce automaticamente il sottopercorso del repository.
  4. Dal telefono visita l’URL. In Chrome scegli «Installa app» dal menu; in Safari scegli Condividi → «Aggiungi alla schermata Home». Dopo la prima apertura online completata, la build funziona offline. Il percorso di sviluppo Vite non è pensato per l’installazione offline.

3. Inserisci il tuo primo conto

  1. Scegli Inizia il mio patrimonio. I dati di esempio non vengono copiati.
  2. Aggiungi voce → Conto corrente e liquidità.
  3. Inserisci nome, saldo contabile, valuta e data → Salva. Disponibilità e somme vincolate sono dettagli dello stesso saldo, non voci da sommare.
  4. Per immobili e debiti inserisci valore totale e la tua quota. La quota del mutuo può essere diversa da quella della casa. Se non conosci un valore, spunta «Valore non ancora disponibile»: il totale sarà dichiarato parziale.

4. Leggi e prova gli insight

  1. In Panoramica scegli il periodo e il formato Gradini / Linee / Colonne. Puoi confrontare il netto oppure attività e debiti. Tocca un punto o usa Tab e frecce per leggerne la data.
  2. La composizione è disponibile come Anello / Barre / Tabella, per categoria, istituto o natura/liquidabilità.
  3. Apri Leggi tra i numeri, scegli due date e prova Cascata / Variazioni / Tabella. La cascata è sospesa se mancano valori. Su telefono scorri il singolo grafico dove necessario; la tabella resta l’alternativa leggibile.
  4. Esporta il grafico in SVG (vettoriale), PNG (immagine) o i dati in CSV. Con gli importi nascosti gli export sono bloccati. In formato Tabella è disponibile il CSV.
  5. Per esplorare grafici già popolati, torna alla copertina dal Profilo → Prova con dati di esempio → «Prova i grafici con sei mesi di storico dimostrativo». Quello storico è dichiaratamente inventato e resta nella sola demo.

5. Importa file e registra operazioni

  1. Aggiungi prima la voce destinataria. Vai in Fonti → Importa saldi o posizioni oppure Importa movimenti.
  2. Scarica uno dei tracciati di esempio dell’app: saldi, posizioni, movimenti. Non sono tracciati ufficiali Fideuram o Trade Republic.
  3. Abbina colonne, conto, valuta e separatore; controlla l’anteprima. Per il dettaglio strumenti spunta posizioni e abbina anche nome/descrizione, quantità e prezzo. Non includere righe totale insieme ai componenti.
  4. I movimenti non modificano automaticamente i saldi. Per un trasferimento tra due conti tuoi usa Patrimonio → Trasferisci.
  5. Per un acquisto o una vendita già eseguiti, oppure per un rimborso di capitale, usa Patrimonio → Registra operazione. Capitale, commissioni e interessi vengono distinti. Non vengono inviati ordini o pagamenti; questa procedura è limitata a posizioni EUR.

6. Usa gli stessi dati su due dispositivi

  1. Sul dispositivo aggiornato: Profilo in alto a destra → Scarica backup strutturato.
  2. Trasferisci il JSON con un mezzo sotto il tuo controllo (per esempio cavo, AirDrop o condivisione locale). Il JSON contiene dati finanziari in chiaro: non metterlo nel repository o in un link pubblico.
  3. Sull’altro dispositivo scegli il patrimonio personale → Profilo → Ripristina backup JSON. Conferma la sostituzione solo dopo aver esportato eventuali modifiche locali da conservare.
  4. Non modificare contemporaneamente entrambe le copie: non esiste fusione o sincronizzazione automatica. Il backup demo si ripristina solo nella demo, quello personale solo nell’archivio personale.

7. Limiti dichiarati e banche

La valuta di riferimento è EUR; puoi conservare valori originali EUR, USD, GBP, CHF, JPY e CAD con cambi manuali datati verso EUR. Non sono presenti quotazioni live, misura del rendimento, importazione PDF/XLSX, automazione di rate o connessioni Fideuram/Trade Republic verificate. Nessuna sandbox bancaria è stata collaudata. Non chiediamo password, PIN o OTP bancari. Usa l’esportazione ufficiale dell’istituto se disponibile e compatibile, oppure inserisci i valori a mano. Non serve comprare un connettore.

Lo schema PostgreSQL opzionale è conservato nel progetto per sviluppi futuri ma non è usato dall’app standard: non devi configurare Supabase né un database. Su un dispositivo condiviso chi usa lo stesso profilo browser può leggere i dati locali.

La pubblicazione del codice e della demo non pubblica i tuoi dati. Non sono stati attivati servizi esterni, conti reali o abbonamenti. Il merge della PR non esegue il workflow Pages: la scelta di pubblicare l’app resta manuale.
